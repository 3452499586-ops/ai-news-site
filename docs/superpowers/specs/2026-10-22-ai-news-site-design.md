# AI 权威资讯聚合网站设计说明

## 1. 项目目的

本项目交付一个中文 AI 权威资讯静态网站。网站首次内置 5—8 条截至交付日公开、可追溯且按既定规则核验的真实资讯，帮助普通读者、开发者和企业快速理解近期 AI 事件及其影响。

网站必须能够直接双击 `index.html` 打开。除用户主动点击外部来源链接外，全部内容展示和交互均在浏览器本地完成。项目交付后不包含自动采集、自动更新、后台服务、云函数、计划任务、分析服务或任何持续费用来源。

## 2. 成功标准

- 无需安装 Node.js、Python、数据库或其他依赖。
- 无需账户、API Key、服务器或网络连接即可浏览全部内置内容并使用全部本地交互。
- 首页展示 5—8 条真实示例资讯，每条均包含完整时间、背景、事实、影响、核验状态和来源。
- 搜索、组合筛选、排序、展开、标签导航和重点资讯手动切换均可在 `file://` 环境工作。
- 页面加载时不产生任何外部请求，不注册 Service Worker，不创建 WebSocket，不执行后台轮询。
- 桌面、平板和移动端均具有清晰的信息层级、键盘可访问性和减少动态效果支持。

## 3. 技术架构

项目采用无构建步骤的原生静态多文件结构：

```text
ai-news-site/
├─ index.html
├─ styles.css
├─ app.js
├─ news-data.js
├─ README.md
├─ assets/
│  ├─ icons/
│  ├─ images/
│  └─ fonts/
├─ docs/
│  ├─ source-policy.md
│  ├─ verification-policy.md
│  ├─ update-guide.md
│  └─ superpowers/specs/2026-10-22-ai-news-site-design.md
└─ tests/
   ├─ app.test.html
   └─ static-audit.ps1
```

`index.html` 提供语义结构和无障碍标记；`styles.css` 实现视觉系统与响应式布局；`news-data.js` 通过 `window.AI_NEWS_DATA` 和 `window.AI_NEWS_META` 暴露本地数据；`app.js` 读取本地数据并完成所有视图渲染和交互。

页面不得使用 `fetch`、`XMLHttpRequest`、WebSocket、动态远程模块、Service Worker、第三方 iframe、远程字体、远程图片、CDN 或运行时 API。

## 4. 数据模型

每条资讯包含以下字段：

- `id`：稳定且唯一的本地标识。
- `title`、`summary`：中文标题与一句话摘要。
- `company`、`region`、`category`：机构、地区和内容类型。
- `eventTime`、`publishedTime`、`verifiedTime`：事件、发布和核验时间。
- `background`、`content`、`importance`：背景、核心事实和行业意义。
- `userImpact`、`developerImpact`：对普通用户及开发者或企业的影响。
- `verificationStatus`：`verified`、`official` 或 `pending`；正式精选不接受 `pending`。
- `uncertainty`：尚不能独立确认的事项；无不确定项时为空字符串。
- `openSourceStatus`、`apiStatus`、`isResearch`：开源、API 和研究属性。
- `tags`：模型、产品、政策、安全等本地标签。
- `sources`：来源名称、来源等级、渠道和外部链接。
- `corrections`：纠错日期、内容和原因；无纠错时为空数组。
- `featured`、`score`：是否进入重点区及其编辑评分。

站点级元数据包含数据日期、最后手动更新时间、覆盖机构和版本说明。所有统计值均从本地资讯数组计算，避免手工维护两套数字。

## 5. 资讯核验与首批内容

首次内容只在开发阶段进行一次性人工检索和核验。优先级依次为：

1. 官方发布页、官方文档、政府或标准机构资料、官方代码仓库。
2. Reuters、AP、Nature、Science、Financial Times、Bloomberg 或 MIT Technology Review 等具有编辑规范的独立来源。
3. 经过确认的机构官方社交账号，仅作为补充证据或线索。

涉及融资、收购、人事、监管、安全事故和争议事件时，必须采用官方原始资料加至少一个相互独立的权威来源。厂商自报性能、用户数量、能力提升或未来计划，在缺少独立验证时统一标记为“官方声明”。

正式精选不接受仅有截图、匿名爆料、单一普通社交账号或不可访问原始链接的信息。论文内容须标明预印本、已接收论文、会议论文或技术报告，不将 arXiv 上传等同于同行认可。

## 6. 页面信息架构

页面从上至下由以下区域组成：

1. 固定顶部导航：站点标志、主要内容分类、来源库、核验方法和本地搜索入口。
2. 今日信号栏：数据日期、条目数、已核验数、官方声明数、最后手动更新时间和覆盖机构。
3. 首屏重点区：左侧为今日最重要事件，右侧为核验概览和来源分布。
4. 搜索与筛选区：搜索词、公司、地区、时间、类型、核验状态、开源状态、API 状态和研究属性。
5. 资讯时间线：按事件时间倒序排列，可展开背景、核心事实、影响、来源、不确定项和纠错记录。
6. 深度背景与来源雷达：汇总本批资讯的主题关系、地区分布和来源等级。
7. 页脚：信源说明、核验方法、更新说明、隐私与版权信息。

重点资讯区最多容纳三条内容，默认不自动播放。用户可使用按钮、键盘和触屏手势手动切换，并获得明确的当前位置提示。

## 7. 视觉系统

视觉概念为“深克拉因蓝中的可信信号档案”。大胆表达集中在首屏克拉因蓝信号场和贯穿页面的时间轴，其余区域保持克制、清晰和适合长文阅读。

### 7.1 色彩

- 克拉因蓝 `#002FA7`：导航、主信号和关键交互。
- 深蓝 `#06143D`：首屏背景和高对比文字区域。
- 墨色 `#101522`：正文标题。
- 纸白 `#F5F7FC`：主要阅读背景。
- 青色 `#7BD7FF`：非状态型辅助信号。
- 绿色 `#29C98A`：已核验。
- 琥珀色 `#FFB84D`：官方声明和注意事项。
- 红色 `#FF5B6E`：错误或待确认状态。

正文不直接大面积置于高饱和蓝色背景。状态信息同时使用文字和形状，不只依赖颜色。

### 7.2 字体

使用系统字体栈：`Noto Sans SC`、`Source Han Sans SC`、`Microsoft YaHei`、`PingFang SC`、`system-ui`、`sans-serif`。不请求在线字体。标题通过字重、字号、行距和版面比例建立编辑感，不使用装饰性远程字体。

### 7.3 布局

桌面首屏采用 8:4 非对称网格，时间线以纵向信号轨道组织内容。条目之间使用分隔线、留白和时间节点建立层级，避免大量同尺寸圆角卡片。移动端改为单栏，并保留信号顺序和状态信息。

### 7.4 动效

页面仅包含一次性的时间轴点亮、筛选结果过渡、详情展开和用户触发的重点资讯切换。动效不持续循环，不使用 WebGL，不自动播放音视频。启用 `prefers-reduced-motion: reduce` 后取消位移、缩放和平滑滚动。

## 8. 本地交互与状态

搜索覆盖标题、公司、模型、摘要、标签和来源名称。筛选器可组合使用，排序支持事件时间从新到旧、从旧到新以及编辑评分。所有计算均基于内存中的本地数组。

当前搜索、筛选和排序状态可写入 URL 查询参数或哈希，便于刷新后保留视图；这一行为不访问网络，也不记录到服务器。不会使用 Cookie、分析存储或浏览器指纹。

详情按钮通过原生按钮控制当前条目的展开区域，并维护 `aria-expanded` 和关联区域标识。数据为空、字段缺失或筛选无结果时，页面显示明确的本地提示，不尝试联网补充内容。

## 9. 可访问性

- 使用 `header`、`nav`、`main`、`section`、`article`、`aside` 和 `footer` 等语义元素。
- 维持正确标题层级，并提供跳至主内容链接。
- 所有表单控件具有可见标签，按钮支持键盘操作。
- 焦点样式清晰，正文对比度目标不低于 4.5:1。
- 核验状态同时提供图形、颜色和文字。
- 手动轮播提供上一条、下一条和当前位置说明，不自动切换。
- 页面响应系统减少动态效果设置。

## 10. 隐私、安全与零消耗边界

项目不使用 Cookie、浏览器指纹、访问日志、位置、摄像头、麦克风、剪贴板、文件上传、推送通知、后台同步、第三方评论、分享组件或用户跟踪。代码和数据文件中不保存密钥。

所有外部来源链接均由用户主动触发，并使用 `target="_blank"` 和 `rel="noopener noreferrer"`。网站打开和浏览过程中不会预连接、预取或预加载第三方域名。

项目不包含部署配置、GitHub Actions、Vercel 配置、数据库配置、云函数、定时任务、自动更新脚本或收费服务依赖。测试脚本只在开发者手动执行时运行，交付网站本身不会自动执行测试。

### 10.1 Codex 额度停止线

本项目实施期间，在进入资讯调研、编码、浏览器验收等主要阶段前，人工读取当前账户可用的 Codex 使用额度。只要系统能够读取的任一 Codex 使用额度窗口剩余量达到或低于 15%，必须立即停止继续执行，保存当前文件和验证结果，并向用户报告停止原因与未完成事项。

不得为继续执行而购买或兑换 Credits、绑定支付方式、开启按量计费、升级套餐、切换到收费服务或创建任何自动额度监控。该规则仅约束本次人工开发过程，不得被实现为交付网站中的脚本、后台任务、轮询或第三方请求。

## 11. 异常处理

- 数据对象缺少非关键字段时，以“未提供”或隐藏对应小节处理。
- 数据对象缺少 `id`、`title`、三类时间或来源等关键字段时，不渲染为正式资讯，并在本地控制台输出明确诊断。
- 不支持 JavaScript 时，页面仍显示网站说明和启用 JavaScript 的提示，不产生外部请求。
- 筛选无结果时，提供清除筛选按钮和当前条件说明。
- 外部来源失效属于人工更新范围，页面不会自动重试、探测或替换链接。

## 12. 测试与验收

测试分为四层：

1. 逻辑测试：搜索、筛选、排序、状态统计和缺失字段处理。
2. 静态审计：检查 HTML、CSS、JavaScript 中是否存在远程资源、网络 API、Service Worker、WebSocket、分析代码、密钥和后台任务迹象。
3. 浏览器测试：通过 `file://` 打开页面，检查搜索、组合筛选、排序、展开、轮播、键盘焦点和移动端布局。
4. 网络验证：使用浏览器开发者工具确认首次加载和本地交互期间没有任何自动外部请求。

所有交付说明将明确：测试脚本和资讯检索只在交付制作阶段由人工主动运行，不会成为网站运行时功能。

## 13. 手动更新流程

后续维护者按以下顺序工作：收集候选资讯、定位官方原始资料、必要时寻找第二独立来源、核对名称与时间及数字和发布状态、筛选 5—8 条、编辑 `news-data.js`、刷新页面、检查筛选和来源、执行静态审计、备份旧版本。

`README.md`、`docs/source-policy.md`、`docs/verification-policy.md` 和 `docs/update-guide.md` 将分别承担使用说明、信源规范、核验规则和非编程更新指导，避免将关键维护知识只留在代码注释中。

## 14. 明确不做的事项

- 自动抓取、自动摘要、自动核验、自动发布或实时更新。
- 后台管理系统、CMS、数据库或用户账户。
- 邮件、通知、监控或计划任务。
- 运行时调用 AI 模型或第三方 API。
- 云部署、自动部署或付费服务集成。
- 广告、统计、行为分析或社交分享组件。
- 将“待确认”内容混入每日正式精选。
- 在任一可读取的 Codex 使用额度窗口剩余量达到或低于 15% 后继续执行项目任务。
- 为绕过额度停止线购买、兑换或自动补充任何付费额度。
